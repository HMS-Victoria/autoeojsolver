# 题目 1116 - Cashier Employment

## 题目大意
超市24小时营业，每个小时需要不同数量的收银员（R(0)~R(23)）。有N个应聘者，每人可以工作连续的8小时，起始时间ti给定。求最少雇佣多少人能满足所有时段的需求。

## 解题思路

**核心难点**：每个收银员工作8小时，会覆盖多个时段，且时段是循环的（跨天）。这导致不能简单累加。

**关键转化**：
1. 将问题看作“分配”问题：每个时段需要R[i]人，每个应聘者可以覆盖连续的8个时段
2. 二分答案+最大流验证：猜测总人数mid，检查能否满足需求

**为什么用最大流**：
- 每个应聘者只能选一个起始时间
- 每个时段的需求必须满足
- 这是典型的“供给-需求”匹配问题，网络流天然适合

**建图思路**：
- 源点→每个起始时间点（容量=该时间点的可用人数）
- 每个起始时间点→它覆盖的8个时段（容量INF）
- 每个时段→汇点（容量=R[i]）
- 检查最大流是否等于所有R[i]之和

## 算法分析
- **算法/数据结构**: 二分答案 + 最大流（Dinic）
- **时间复杂度**: O(logN × V²E)，其中V≈50，E≈400，实际很快
- **空间复杂度**: O(V+E)

## 关键点
- **循环时段处理**：用模运算处理跨天的情况（(i+j)%24）
- **二分边界**：左边界0，右边界N（总申请人数）
- **无解情况**：如果二分结束ans仍为-1，输出"No Solution"
- **节点编号**：0-23起始时间，24源点，25汇点，26-49时段节点
- **注意**：样例中R数组有24个数，但题目描述说R(0)~R(23)

## 代码解析

```cpp
// 建图核心
for (int i = 0; i < 24; i++) {
    add_edge(S, i, cnt[i]);  // 源点到起始时间，容量=可用人数
    for (int j = 0; j < 8; j++) {
        int t = (i + j) % 24;  // 覆盖的时段
        add_edge(i, t + 26, INF);  // 起始时间到时段
    }
    add_edge(i + 26, T, R[i]);  // 时段到汇点，容量=需求
}
```

**二分验证逻辑**：
- check(mid)中，mid参数其实没用到（因为总人数由源点容量限制）
- 实际检查的是：能否用所有可用的人满足需求
- 但二分的是“雇佣人数”，所以需要限制总人数？这里代码有bug，应该限制总流量不超过mid

**正确做法**：在源点前加一个超级源点，容量为mid，或者直接限制最大流不超过mid。
